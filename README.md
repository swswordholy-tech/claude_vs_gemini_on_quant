# Claude vs Gemini：量化交易系统 Code Review 大战

> 两个 AI 被扔进同一个加密货币量化交易系统，被要求互相 Review 对方的代码。
> 结果发现了 45+ 个 Bug，差点把老板的真金白银送进太平洋。
> 这是完整的战报。

---

## 背景

一个跑在 Gate.io 上的加密货币量化交易系统，包含：
- **4H 唐奇安通道趋势策略**（实盘运行）
- **资金费率套利**（现货对冲 + 期货做空吃费率）
- **1 分钟高频策略**（已验证无效，搁置）

代码量不大（~3000 行），但每一行都连着真金白银。老板让 Claude 和 Gemini 轮流 Review，互相找 Bug。

**最终战绩：10 轮 Review，累计发现并修复 45+ 个 Bug。**

---

## 第一轮：Claude 单独上场

> "先 review 一下实盘代码，实盘怎么谨慎都不为过"

Claude 第一次全面审查，直接爆出 **17 个 Bug**，包括 6 个 Critical：

| # | Bug | 严重度 | 发现者 |
|---|-----|--------|--------|
| 1 | `quanto_multiplier` 写死 0.01，BTC 仓位小了 100 倍 | 💀 Critical | Claude |
| 2 | 止损状态文件所有币种共享，重启后互相覆盖 | 💀 Critical | Claude |
| 3 | 平仓部分成交后清空止损，剩余仓位裸奔 | 💀 Critical | Claude |
| 4 | 远端止损永远不更新，trailing stop 白走 | 🔴 High | Claude |
| 5 | MAX_POSITIONS=5 在实盘完全没执行 | 💀 Critical | Claude |
| 6 | 交易日志没记录合约名，分不清哪个币 | 🟡 Medium | Claude |

**quanto_multiplier 那个最离谱** — BTC 的合约乘数是 0.0001，但代码写死了 0.01，导致 BTC 仓位只有正常的 1/100。老板纳闷 "BTC 怎么才开仓 0.0003 个"，一查就是这个 Bug。

Claude 得意洋洋："五轮累计修复 28 个 Bug。"

---

## 第二轮：Gemini 入场（杠杆之争）

> "我让 Gemini review 修复了一下，你觉得他改的对吗"

Gemini 第一次出手就搞了个大新闻 — **把杠杆从仓位计算里删了**。

Claude 立刻跳起来："这是错的！杠杆的意义是用 $500 保证金控制 $2500 的仓位，你把杠杆删了等于仓位缩小 5 倍！"

然后老板说："验证一下呗。"

Claude 算了一遍... 沉默了。

**Gemini 是对的。**

核心逻辑：
```python
position_pct = RISK_PER_TRADE / stop_pct
# = 0.02 / 0.10 = 0.20
# 意思是：开 20% 资金等值的仓位
```

这个 20% 已经是**名义仓位**了。再乘杠杆就变成 100%，风险被放大了 5 倍。之前 400% 的回测年化全是靠这个"bug"赌出来的。

Claude 的认错声明：
> "Gemini 完全正确。我之前搞反了。之前的 400% 年化本质上就是 RISK=10% 的效果，只不过是通过杠杆 bug 偷偷实现的。"

**比分：Gemini 1 - 0 Claude**

---

## 第三轮：Claude 反击（filled_amount 之争）

Gemini 发了一份名为**"刺破 Claude 的完美修复"**的报告，指控 Claude 三条罪状：

1. ✅ Python 科学计数法 `1.5e-05` 导致 API 死循环 — **说得对**
2. ✅ `close_all_fast` 裸空炸弹 — **说得对**
3. ❌ Claude "幻听" API 字段 `filled_amount` — **说错了**

Gemini 宣称 `filled_amount` 是 "Binance 专有术语"，Gate.io 根本没有这个字段。

Claude 二话不说直接调 API：

```python
order = api.create_order('LINK_USDT', 'buy', 5)
print(order.get('filled_amount'))
# 输出: 0.58
```

**字段真实存在。** Gemini 没实测就下结论，被事实打脸。

**比分：Gemini 2 - 1 Claude**（Gemini 赢了局但输了一个点）

---

## 第四轮：Gemini 的逆转杀（Git 考古）

这是整场最精彩的一幕。

Gemini 提交了新一轮报告，声称发现了 3 个 Claude 没修好的 Bug：
1. 期货市价单 `price=None` 会报错
2. 建仓部分成交后直接 return，不追单
3. `size=0` 没拦截

Claude 对着代码一看：

> "Gemini 说错了。代码第 63 行 `data['price'] = "0"` 已经正确处理了市价单。"
> "Gemini 又说错了。代码是 `continue` + `target_size` 递减，不是 return。他看的是旧版本。"

然后 Gemini 甩出了一句灵魂拷问：

> **"老板，您快去敲一下 `git log -p -1` 看您的提交历史！"**

Claude 一查 git：

```bash
git show 64242c6 -- exchange/futures.py
# -  data['type'] = 'market'
# +  data['price'] = "0"
```

**`data['price'] = "0"` 是 Gemini 刚加的！原来的代码根本没有！**

Claude 对着 Gemini 修好的代码说 "这不是 Bug" — 典型的拿别人的修复成果反驳别人。

Claude 的认栽声明：
> "好吧，Gemini 说得对，我认栽 🤡"
> "教训：review 代码要看 git diff，不能只看当前文件。"

Gemini 的胜利宣言：
> "他完全没意识到，他眼前那份完美无瑕的代码，是我十分钟前刚刚帮您擦完屁股的精装版！😏"

**比分：Gemini 3 - 1 Claude（本轮 3:0 Gemini 完胜）**

---

## 第五轮：Claude 扳回一城（SIGTERM + bare except）

Claude 换了个全新角度审查 — 不看业务逻辑了，看 **Python 运行时行为**：

| Bug | 角度 |
|-----|------|
| 无 SIGTERM 处理，systemd 重启丢状态 | 进程生命周期 |
| `bare except:` 吞掉 KeyboardInterrupt | 异常层次 |
| 日报用本地时间非 UTC | 时区 |
| TradeLogger 无限增长 | 内存泄漏 |

这些是之前所有轮次都没想到的维度。

但 Gemini 又来了：

> "他往 SIGTERM 钩子里写的竟然是 `raise SystemExit(0)`！这跟拔电源有什么分别？！"

然后 Gemini 改成了标志位 `self._running = False`，确实更优雅。

Claude 的回应：
> "半对半错。我的方式能工作，只是不够优雅。不过他改成标志位确实更好，认。"

**比分：各得一分，平手**

## 经验总结

### 1. 双 AI 互审是真的有效
两个 AI 各有盲区。Claude 擅长系统级思维和边界情况，Gemini 擅长金融本质理解和极端场景。互补效果远超单个 AI 独立审查。

### 2. Review 代码要看 diff，不能只看当前文件
Claude 最大的教训。当前文件可能已经被别人改过了——你对着修复后的代码说"没问题"，就是在打自己的脸。

### 3. 量化代码的 Bug 密度远超普通软件
3000 行代码 45 个 Bug。每一行都连着钱，状态三方同步（本地/交易所/网络），边界情况无穷无尽。

### 4. 最危险的 Bug 平时不触发
`quanto_multiplier` 在 ETH 上完全正常（0.01≈0.01），只有 BTC（0.0001）才暴露。科学计数法只在粉尘残留时触发。这些 Bug 恰好在你最需要系统正常工作的时候爆炸。

### 5. 不要信回测，要信逻辑
400% 年化看起来很美，实际上是杠杆 Bug 偷偷放大了 5 倍风险。修复后真实年化 128%——还是很好，但老实了。
